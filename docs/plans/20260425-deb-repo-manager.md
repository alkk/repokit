# Minimalistic Debian Repository Manager (debrepo)

## Overview

Build a small Go CLI that manages a static Debian apt repository served from disk and rsynced to a CDN. It supports multiple distros and multiple suites per distro, with isolated per-(distro,suite) pools (no cross-suite dedup), SQLite-backed metadata so package hashes are computed once and persisted (unlike freight, which recomputes), explicit publish-and-sign step using gpg-agent, and fast add/list/search/delete operations even at ~100 GB / thousands of packages.

The output is a fully static tree (`pool/` + `dists/`) that any apt client can consume after rsync.

**Deliberate v1 omissions** (documented so consumers aren't surprised):
- No `Contents-<arch>` files (used by `apt-file`, not by `apt-get` itself).
- No `by-hash/` directories (`Acquire-By-Hash: no` in Release).
- No `Sources` indexes (binary-only).
- No `Packages.zst` (gz + xz only — sufficient for all current apt clients).

## Solution Overview

Single static Go binary `debrepo`. The repo root contains:

- `repo.db` — SQLite, single source of truth for metadata (per-package row with full control stanza + four hashes).
- `config.yaml` — signing key id and per-suite Release header fields.
- `pool/<distro>/<suite>/<component>/<letter>/<source>/<pkg>_<ver>_<arch>.deb` — physical .debs, no cross-suite reuse.
- `dists/<distro>/<suite>/...` — generated apt index tree, fully derivable from DB + pool.

Mutation commands (`add`, `delete`) only touch the DB and pool. The explicit `publish` command rebuilds `dists/<distro>/<suite>` for the requested scope and signs `Release` via gpg-agent. The build is staged in `dists/<distro>/<suite>.new/` and atomically renamed into place.

Hashes (md5/sha1/sha256/sha512) are computed once at `add` time from a single read of the `.deb`, stored in SQLite, and re-emitted verbatim on every `publish` — this is the key win over freight-style tools.

## Technical Details

### Storage layout

```
<repo-root>/
├── repo.db
├── config.yaml
├── pool/
│   └── <distro>/<suite>/<component>/<letter>/<source>/<pkg>_<ver>_<arch>.deb
└── dists/
    └── <distro>/<suite>/
        ├── Release
        ├── Release.gpg
        ├── InRelease
        └── <component>/binary-<arch>/{Packages,Packages.gz,Packages.xz}
```

`<letter>` = first letter of source name (or package name if no Source field), lowercased. Names beginning with `lib` use `lib<second-letter>` (Debian convention).

### SQLite schema

```sql
CREATE TABLE packages (
    id            INTEGER PRIMARY KEY,
    distro        TEXT NOT NULL,
    suite         TEXT NOT NULL,
    component     TEXT NOT NULL,
    architecture  TEXT NOT NULL,
    name          TEXT NOT NULL,
    version       TEXT NOT NULL,
    filename      TEXT NOT NULL,         -- pool-relative path
    size          INTEGER NOT NULL,
    md5           TEXT NOT NULL,
    sha1          TEXT NOT NULL,
    sha256        TEXT NOT NULL,
    sha512        TEXT NOT NULL,
    control       TEXT NOT NULL,         -- verbatim control stanza
    added_at      INTEGER NOT NULL,
    UNIQUE (distro, suite, component, architecture, name, version)
);
CREATE INDEX idx_pkg_lookup    ON packages(distro, suite, component, architecture);
CREATE INDEX idx_pkg_name_ver  ON packages(name, version);
CREATE INDEX idx_pkg_sha256    ON packages(sha256);

CREATE TABLE meta (key TEXT PRIMARY KEY, value TEXT NOT NULL);
-- known meta keys: schema_version, last_publish_at
```

### Config (`config.yaml`)

```yaml
signing_key: "DEADBEEF1234..."          # gpg key id or fingerprint
suites:
  debian/bookworm:
    origin: "MyRepo"
    label: "MyRepo"
    suite: "bookworm"
    codename: "bookworm"
    description: "Internal builds for Debian 12"
  debian/bullseye:
    origin: "MyRepo"
    ...
```

Per-suite blocks are keyed by `<distro>/<suite>`. Missing fields fall back to sensible defaults derived from the key.

### Add flow

1. Open .deb (it's an `ar` archive).
2. Find `control.tar` or `control.tar.{gz,xz,zst}` entry (uncompressed legal in older .debs).
3. Extract `control` file from inside; capture the verbatim text. **Normalise**: strip all trailing whitespace and blank lines, then ensure exactly one trailing `\n`. This is the canonical form that gets stored in `packages.control` and re-emitted on publish.
4. Parse `Package`, `Version`, `Architecture` from the stanza. For `Source`, accept the bare name OR `name (version)` form — strip any ` (...)` suffix and use only the bare name for pool sharding.
5. Compute md5/sha1/sha256/sha512 in a single pass over the .deb file via `io.MultiWriter`.
6. Compute pool path; **stream-copy** the .deb bytes (not rename — source may be on another filesystem) to `<root>/<poolPath>.tmp`, `fsync` the file, `rename` to final name, then `fsync` the parent directory so the rename is durable across power loss.
7. `INSERT` row inside a single SQLite transaction; on any error roll back, remove the `.tmp`, and remove any pool files this batch already promoted to final names earlier in the same call.
8. Default duplicate NVRA → error with hash diff. `--replace` deletes prior pool file and overwrites row.

### Publish flow (per scope `(distro, suite)`)

1. Clean up any leftover `<distro>/<suite>.new` and `<distro>/<suite>.old` from a prior crashed run.
2. Build `dists/<distro>/<suite>.new/`.
3. For each `(component, architecture)` in DB for this suite, stream-write each row's stored `control` (already normalised — single trailing `\n`) followed by `Filename:`/`Size:`/`MD5sum:`/`SHA1:`/`SHA256:`/`SHA512:`, then a single blank line as stanza separator. Fan-out writer simultaneously produces `Packages`, `Packages.gz`, `Packages.xz` and captures size + four hashes of each.
4. Include `architecture=all` rows in every `binary-<arch>/Packages` (apt convention — there is no `binary-all` directory).
5. Build `Release`:
   - Header fields: `Origin`, `Label`, `Suite`, `Codename`, `Description` from `Config.SuiteOrDefault`, `Date` formatted as `Mon, 02 Jan 2006 15:04:05 +0000` (apt rejects literal `UTC`), `Architectures:` listing only concrete arches present (excluding `all`), `Components:` listing concrete components, and `Acquire-By-Hash: no` (explicit, required).
   - Checksum blocks `MD5Sum:`/`SHA1:`/`SHA256:`/`SHA512:` listing every `Packages`/`Packages.gz`/`Packages.xz` with size and hash, paths relative to `dists/<distro>/<suite>/`.
6. Sign via the `Signer` interface — production impl shells out to `gpg --default-key <id> --batch --yes --digest-algo SHA256 --clearsign` for `InRelease` and `gpg --default-key <id> --batch --yes --digest-algo SHA256 --armor --detach-sign` for `Release.gpg`. `--digest-algo SHA256` is required because gpg's default SHA1 is rejected by modern apt. gpg-agent provides the key.
7. Atomic swap on the same filesystem: rename live → `<suite>.old`, rename `<suite>.new` → live, `rm -rf <suite>.old`. `fsync` parent directory after each rename for durability.
8. Update `meta.last_publish_at`.
9. Pool is never touched by publish.

### Module layout (Go)

Following go-developer conventions: multi-package single-binary layout with `cmd/<binary>/main.go` + `pkg/<name>/`. Flat package structure, one concern per package. One `_test.go` per source file (e.g. `repo.go` → `repo_test.go`); cross-cutting integration tests live in `pkg/cli/integration_test.go` as the documented exception. Mocks generated by `matryer/moq` go in `pkg/<pkg>/mocks/`.

```
cmd/debrepo/        main.go (entrypoint + run())
pkg/config/         load + validate config.yaml
pkg/repo/           DB open, migrate, query, transaction helpers
pkg/deb/            .deb parsing: control extraction, arch detection, hashing
pkg/pool/           pool path computation, atomic write/delete
pkg/index/          Packages and Release writers (with gz/xz tee)
pkg/sign/           Signer interface + gpg implementation + nopSigner; mocks/ generated by moq
pkg/cli/            per-command implementations (init/add/delete/list/search/publish/verify/info)
vendor/             committed; refreshed via `go mod vendor` after every dep change
```

**Code conventions** (apply throughout):
- Errors wrapped with context: `fmt.Errorf("opening %s: %w", path, err)`. Sentinel errors as exported `ErrFoo` vars (e.g. `repo.ErrDuplicate`).
- Interfaces defined on the **consumer side** and kept small (e.g. `cli` defines a `Signer` interface it accepts; `sign` package exports the concrete `GPGSigner`).
- Context as first param on every blocking/IO method (`Repo.Insert(ctx, tx, p)` etc.) — even when SQLite calls don't strictly need it, keep the signature for cancellation hygiene.
- Comments lowercase single-line; godoc on exported identifiers starts with the identifier name.
- Compiled regex at package scope (`var srcVerSuffix = regexp.MustCompile(\` \\(.*\\)$\`)` for stripping `Source: name (version)`).
- Tests use `testify/require` (fatal preconditions) + `testify/assert` (non-fatal). Table-driven with `t.Run("case name", ...)`. Filesystem work via `t.TempDir()`. Helpers call `t.Helper()` first line.
- Linter: `golangci-lint` v2 with project's `.golangci.yml`. `make lint` clean is a precondition for every task completion.
